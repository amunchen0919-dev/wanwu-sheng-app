# 架构与数据流

## 正式用户流程

首页 → 节奏/声音选择 → 编曲准备 → 等待任务 → 播放/混音/下载 → 保存 → 我的音乐。

声音优先和节奏优先两种顺序共享同一CreationContext。普通返回保留草稿，新建重置节奏与选择；已保存音频不删除，未知付费任务仍保留锁。

## 创作与AI

RhythmEvent和SoundAsset → extractMusicIntent → buildIntentPrompt → 共享audioLabClient → Node服务 → Stable Audio Text-to-Audio。输入优先使用真实事件，不从混合WAV反推节奏。BPM展示估计及半倍速歧义，个人录音内容、调性和生成歌曲真实拍点不冒称已识别。

API Key只在后端环境变量中。正式页和实验室复用同一付费提交、服务任务库与结果查询。默认90秒，不将30秒参考音频传给Text-to-Audio。Audio-to-Audio仅保留为实验室旧模式。

提交前保存任务ID，并再次核对服务模式、实例和费用。只有用户当次确认与主动点击才能发出Live生成。后续有限GET查询，未知状态不重新POST、不自动解锁；任务/审计元数据留在本机 `.audio-lab/`，不随Git上传。

## 音频与存储

Web Audio负责节奏及素材播放，MediaRecorder负责真实录音。IndexedDB版本2保留sounds/blobs并新增music仓，存储原曲、混音、来源、输入快照、质量和保存状态。未保存缓存不冒充作品列表，保存成功页以实际事务结果为准。刷新可读取本地作品或只查询既有任务。

后期混音可关闭，只取少量真实短素材，使用包络、均衡、声像和短延迟，原曲始终保留。没有可靠的生成曲目节拍/调性跟踪，采用段落附近的保守点缀。长静音或时长异常拒绝混入；峰值单项告警可做音量留量，但不修复已有失真。

质量检查统计100ms窗口RMS、总时长、有效覆盖、最长/结尾近静音及疑似削波。失败不自动重新付费；技术指标不代替音乐审美或VoiceOver人工验收。

## Mock、配置与边界

无密钥默认Mock。`npm run dev:api:mock`明确指定免费服务；正式页也有明确标注的本地免费体验，使用确定性测试音频而非冒充AI。Live由使用者配置密钥并主动启动，价格与来源在确认页展示。

本地API绑定127.0.0.1:8787；Vite开发5173和构建预览4173代理同一服务。当前按本机使用设计，公网部署还需要独立的用户鉴权、限额和运维设计。

16页语义与键盘回归、录音API模拟、数据库事务协议、费用保护、Mock端到端与真实PCM混音由自动测试覆盖。真实AI听感、完整屏幕阅读器体验和不同设备仍需人工验收。
